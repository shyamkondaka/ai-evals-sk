## Fallback methods (non-Level 3 items)

### L2 · Context Specificity (UX Trust · P1)
- **Method:** Run a lightweight post-call sentiment ratio check that flags any response containing disproportionate positive/neutral content against a query that explicitly requested negatives only, and surfaces a caveat to the user before they act on it.
- **Why this fallback is defensible:** Because the data integrity is intact — the model is misapplying a scope constraint, not fabricating reviews — so the fallback doesn't need to prevent the failure entirely, it needs to ensure the user is never silently misled by it, which this caveat mechanism achieves at near-zero cost while a full constraint-adherence eval suite is built out.

### L2 · Data Bias (Fairness · P2)
- **Method:** Run a pre-call geographic distribution check that detects region-specific query intent and injects an explicit regional balance directive into the system prompt, combined with a post-call source audit that flags responses where cited data points fall below a minimum APAC representation threshold.
- **Why this fallback is defensible:** Because this failure is detectable at the data-sourcing layer before it becomes a strategic decision — if you can show that every response flagged for APAC underrepresentation was caught and labeled before a business decision was made on it, you have a documented gap with a visible guardrail rather than a silent bias that only surfaces when a regional team notices their market is missing from a six-month strategy deck.
